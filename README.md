# 3AM SDC Hackathon

A career-development prototype combining Pathwaay’s career/SDG scenario demo with profile-linked AI research signals and a cached job-posting snapshot.

## Local development

Requires Python 3.10+ and Node.js 22.18+ (Node 24 recommended). Use npm inside `src/frontend`; this repository is not a pnpm workspace.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm --prefix src/frontend ci
python scripts/dev.py
```

Open http://localhost:3000. The launcher starts FastAPI on 127.0.0.1:8080 and Next.js on port 3000, and stops both when interrupted or either service exits. `PORT` and `API_PORT` can override these development ports. The launcher requires a POSIX environment (macOS/Linux/Replit).

Alternatively, run each service in its own terminal:

```sh
python -m uvicorn src.main:app --host 127.0.0.1 --port 8080 --reload
npm --prefix src/frontend run dev
```

Next.js proxies `/api/*` to `BACKEND_URL` (default `http://127.0.0.1:8080`). FastAPI docs are at http://127.0.0.1:8080/docs. SQLite defaults to `src/data/future_ready.sqlite3`; set `APP_DB_PATH` to change it. Keep local data and credentials out of Git.

## Pages and integration

| URL | Behavior |
| --- | --- |
| `/` | Redirects to `/register`, matching main |
| `/register`, `/login` | Main’s onboarding/sign-in previews; no account creation or authentication |
| `/signals` | Profile skill → related AI skill → work change, with inspectable source passages |
| `/explorer` | Career matching, SDG mapping and synthetic scenario demo |

The skills workspace has two navigation destinations: AI trend signals and Career demo. Both use the shared workspace ribbon. The signals page starts with a fictional profile, lets the learner switch profiles and select one of that profile’s listed skills, then shows at most three supported AI-skill connections. The career demo uses generated synthetic career data. Former workspace URLs redirect to `/signals`. Onboarding answers remain in memory and are not silently copied into a profile. No page implements account security.

## Pathwaay model and data

The synthetic data is stored in `data/` at the repository root. Recreate it with `node scripts/generate_synthetic_data.mjs`, then train the local CPU models with `python scripts/train_career_models.py`. Model artifacts are saved under `models/` and excluded from Git; the backend trains them from the committed CSVs when needed. The SDG ranker uses curated synthetic skill-to-target weights across all 17 goals. SDG explanations can be generated by the optional RunPod GLM endpoint; configure `RUNPOD_API_KEY` and `RUNPOD_LLM_ENDPOINT_ID` in the backend environment. Career inference uses the local scikit-learn model by default, or an optional RunPod career endpoint when `RUNPOD_ENDPOINT_ID` is configured.

## Replit and production

After installing Python and frontend dependencies, the Replit Run button uses `scripts/dev.py`. Only the frontend needs a public port; it proxies API calls to the local backend. The previous artifact/workspace configuration and unrelated database post-merge hook have been removed.

For a production server, build with `npm --prefix src/frontend run build`, run FastAPI without `--reload`, and run `npm --prefix src/frontend run start`. Configure `BACKEND_URL` when building if the API is not at the default address. Replit deployment and durable SQLite storage must be configured and verified separately; the development launcher is not a production deployment configuration.

RunPod is optional. FastAPI can use the local career model without RunPod. Generated SDG explanations require a configured RunPod language-model endpoint; the fixed SDG reference text and dataset-ranked goals do not. `runpod/handler.py` is a Serverless handler for career inference and requires the included synthetic dataset at deployment.

## AI Trend Signals data

`/signals` reads `GET /api/trends/connections?sample_id=cs-student&skill_id=local:python-programming`; a saved demo profile can be supplied with `profile_id` instead. A normal GET reads the profile and versioned SQLite connections only. It never fetches providers or invokes RunPod. The background refresh checks Remote OK and OpenAlex at most daily and DOSM at most weekly when due, retains the last good source data on failure, and rebuilds shared findings and skill connections. Set `EVIDENCE_AUTO_REFRESH=0` to disable it. When a new installation has no retained job descriptions, the page gives an honest empty state until the next successful refresh. Previous caches containing only title and tags cannot support the new passage-level connections.

The first version uses a small, reviewed set of candidate skill links in `src/data/skill_connection_rules.py`. A candidate becomes displayable only when the retained job description contains exact supporting passages. Extraction is cached by source ID, document ID, content hash and extraction version; published connections have an evidence version. The evidence drawer links to the original posts and separates the observed wording from the reviewed interpretation. Conditional posting counts show numerator, denominator, sample scope and dates only when the pairing can be measured. A current co-occurrence or shared task does **not** establish job-demand growth, statistical correlation, skill decline, or replacement. A database-search analogy has no numeric pairing count because the source does not name the profile skill. The evidence is a bounded mixed-location remote feed, so it is not a Malaysian labor-market estimate. OpenAlex research data remains in the backend for other endpoints but does not drive these work-connection cards. The Career Demo’s synthetic model remains separate.

Optional model extraction and wording run only from the operator CLI, never from a page request. With `EVIDENCE_LLM_ENABLED=1`, `RUNPOD_LLM_ENDPOINT_ID`, `RUNPOD_API_KEY`, `EVIDENCE_LLM_REQUEST_BUDGET` and `EVIDENCE_LLM_TOKEN_BUDGET` configured, run `.venv/bin/python -m scripts.prepare_skill_connection_model extract DOCUMENT_ID` or `... explain CONNECTION_ID`. The prompts have separate versions and validated JSON output; extraction quotes must occur in the retained description and wording must cite saved evidence IDs. Cached results are shared across profiles and keyed by source/evidence and prompt/model versions. Requests, input length, output tokens and retries are bounded. The token limit is based on reported or estimated tokens, not actual dollar billing; it is **not** a guaranteed spending cap. When inference is disabled, unavailable, or invalid, the reviewed template remains available. No paid infrastructure is created by the app.
