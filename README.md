# 3AM SDC Hackathon

A career-development prototype combining Pathwaay’s onboarding and career/SDG scenario demo with Aiversecity’s saved fictional profiles, CV tools, research evidence and employment snapshots.

## Local development

Requires Python 3.10+ and Node.js 22.18+ (Node 24 recommended). Use npm inside `src/frontend`; this repository is not a pnpm workspace. The development launcher supports Windows, macOS and Linux.

Windows PowerShell:

```sh
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
npm --prefix src/frontend ci
python scripts/dev.py
```

macOS/Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm --prefix src/frontend ci
python scripts/dev.py
```

Open http://localhost:3000. The launcher starts FastAPI on 127.0.0.1:8080 and Next.js on port 3000, and stops both when interrupted or either service exits. `PORT` and `API_PORT` can override these development ports.

Alternatively, run each service in its own terminal:

```sh
python -m uvicorn src.main:app --host 127.0.0.1 --port 8080 --reload
npm --prefix src/frontend run dev:frontend
```

Next.js proxies `/api/*` to `BACKEND_URL` (default `http://127.0.0.1:8080`). FastAPI docs are at http://127.0.0.1:8080/docs. SQLite defaults to `src/data/future_ready.sqlite3`; set `APP_DB_PATH` to change it. Keep local data and credentials out of Git.

| URL | Behavior |
| --- | --- |
| `/` | Redirects to `/register`, matching main |

| `/explore` | Skills catalogue with profile, research and posting filters |
| `/radar` | OpenAlex research and Remote OK job-source evidence |

The career demo links to the workspace, and the workspace links back. Onboarding answers remain in memory and are not silently copied into saved profiles. Use fictional details only. Pathwaay's role matches, scenario estimates, and SDG rankings demonstrate the workflow using generated synthetic data; they are not real labour-market forecasts or measured SDG impact. No page implements account security.

## Pathwaay model and data

The synthetic data is stored in `data/` at the repository root. Recreate it with `node scripts/generate_synthetic_data.mjs`, then train the local CPU models with `python scripts/train_career_models.py`. Model artifacts are saved under `models/` and excluded from Git; the backend trains them from the committed CSVs when needed. The SDG ranker uses curated synthetic skill-to-target weights across all 17 goals. SDG explanations can be generated by the optional RunPod GLM endpoint; configure `RUNPOD_API_KEY` and `RUNPOD_LLM_ENDPOINT_ID` in the backend environment. Career inference uses the local scikit-learn model by default, or an optional RunPod career endpoint when `RUNPOD_ENDPOINT_ID` is configured.

Route-group names in parentheses do not appear in URLs. Separate root layouts prevent the two existing global stylesheets from affecting each other. Crossing between groups performs a full page load; saved fictional profiles remain available through the existing browser profile ID and SQLite storage.

## Replit and production

After installing Python and frontend dependencies, the Replit Run button uses `scripts/dev.py`. Only the frontend needs a public port; it proxies API calls to the local backend. The previous artifact/workspace configuration and unrelated database post-merge hook have been removed.

For a production server, build with `npm --prefix src/frontend run build`, run FastAPI without `--reload`, and run `npm --prefix src/frontend run start`. Configure `BACKEND_URL` when building if the API is not at the default address. Replit deployment and durable SQLite storage must be configured and verified separately; the development launcher is not a production deployment configuration.

RunPod is optional. FastAPI can use the local career model without RunPod. Generated SDG explanations require a configured RunPod language-model endpoint; the fixed SDG reference text and dataset-ranked goals do not. `runpod/handler.py` is a Serverless handler for career inference and requires the included synthetic dataset at deployment.

remain the foundation. The workspace navigation additionally links to
**`/role-matching`**, which hosts KW's independent ESCO matching and reskilling
workflow. `/` still redirects to `/register`. The saved-profile/local-vocabulary
and ESCO profile formats remain separate; no automatic conversion is performed.

The ESCO workflow retains verified citations, full-index skills/title search,
backend profile-relevance scoring, recommendation qualification rules and
reviewed learning resources with honest incomplete coverage. Its API paths
(`/api/matches`, `/api/pathways`, `/api/v2/*`, `/api/v2.1/roles/search`, and explicit
`/api/esco/*` lookup) retain their existing contracts. Synthetic career/scenario
scores and ESCO profile relevance have different meanings and are not combined.

Implementation: `src/api/future_roles.py`, `src/models/future_roles.py`,
`src/models/future_role_discovery.py`, `src/services/future_roles/`,
`src/services/sources/esco.py`, and the frontend `(workspace)/(future-ready)` route group (shared workspace navigation).

Existing ESCO datasets, CSV exports, source registries, resource catalogues and
export/build scripts remain under `data/` and `scripts/`. Application startup
does not download ESCO. See `docs/FUTURE_ROLE_IMPLEMENTATION.md` and

Install the backend test dependency with `python -m pip install -r requirements-dev.txt`.

### Future-Role Matching presentation/profile handoff

`/role-matching` now uses compact cards and separate canonical-role details and
pathway routes. `PathwayView`, backend contracts, scoring and datasets are unchanged.
Role Matching reads the saved Profile reference already stored by the workspace
and retrieves `/api/v2/profiles/{profile_id}` on entry and after refresh. This
read-only adapter preserves the workspace profile contract and resolves claimed
skills against exact ESCO preferred/alternative labels. Existing local vocabulary
aliases are used only when saved labels have no exact match. Ambiguous and unknown
skills remain unresolved and excluded from scoring; no interests or desired skills
become claimed skills. Duplicate concepts count once. Zero weekly hours become an
unavailable pathway schedule, preserving the existing positive-hours contract.
Changes to saved skills invalidate cached recommendations on the next visit.
The optional `setCurrentFutureRoleProfile` handoff remains available. No CV or
additional profile contents are persisted in the browser. Without a saved profile,
the UI requests one; stale references and retrieval failures show retryable errors.
Development/tests may explicitly use `/role-matching?demo=demo-graduate-a`;
production never chooses a fixture implicitly.

## AI Trend Signal deployment

The backend now populates missing O*NET/Anthropic references and refreshes job
postings, extracted connections and OpenAlex research in a background worker.
Fresh deployments do not require copying a developer's private SQLite database.
The first import can take several minutes; reload `/signals` after it completes.
A bundled, dated OpenAlex snapshot seeds an empty research cache so shared-IP
rate limits do not leave the chart blank; its original query URLs and collection
timestamps remain visible. Live refreshes replace it on success.
Existing valid references are reused, postings are refreshed at most daily, and
research follows its existing hourly cooldown. A database lease prevents workers
sharing the same SQLite file from repeating a refresh. Provider failures remain
independent and retain last-good data. Check backend logs for `AI Trend Signal`.

Configure these **deployment** secrets/settings (not frontend environment variables):

- `OPENALEX_API_KEY`: a free key from https://openalex.org/settings/api. Anonymous
  queries share the hosting IP's budget and can return HTTP 429. Short throttles
  are retried; exhausted daily budgets require a reset or a dedicated key.
- `RUNPOD_API_KEY` and `EVIDENCE_LLM_ENABLED=1`: required for generated disruption
  assessments and evidence explanations. `RUNPOD_LLM_ENDPOINT_ID` can override
  the existing team endpoint. Public evidence collection itself never calls the LLM.
- `AI_TREND_AUTO_REFRESH=0`: disable network maintenance for offline runs/tests.
- `APP_DB_PATH`: use durable storage when available. Replit's deployment-local
  filesystem is not a durable database; rebuilt instances can need rehydration.
  This refresh mechanism rebuilds public evidence only, not user profiles.

For Replit: sync/pull GitHub `main` into the Replit project, check Publishing's
commands and secrets, then **Republish**. A GitHub push alone does not replace
Replit's published snapshot unless separate automation was configured. Retain
this app's existing build/run configuration. After publishing, verify
`/api/trends/disruption-occupations` has `source_status.ready=true` and nonempty
occupations, `/api/trends` contains observations, and `/signals` shows a nonempty
posting sample. A skill can still legitimately have no supported connection.

Manual maintenance against the backend's `APP_DB_PATH`:

```sh
python -m src.services.signal_maintenance
# Or refresh the individual source groups:
python -m scripts.refresh_disruption_references
python -m scripts.refresh_ai_trend_evidence
```

Run isolated backend verification without external background calls:

```sh
AI_TREND_AUTO_REFRESH=0 python -m unittest discover -s tests
```
