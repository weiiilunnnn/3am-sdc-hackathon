# 3AM SDC Hackathon

A career-development prototype combining Pathwaay’s career/SDG scenario demo with profile-linked AI research signals and a cached job-posting snapshot.

## Local development

Requires Python 3.10+ and Node.js 22.18+ (Node 24 recommended). Use npm inside `src/frontend`; this repository is not a pnpm workspace.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm --prefix src/frontend ci
python scripts/dev.py
```

Open http://localhost:3000. The launcher starts FastAPI on 127.0.0.1:8080 and Next.js on port 3000, and stops both when interrupted or either service exits. `PORT` and `API_PORT` can override these development ports. The launcher requires a POSIX environment (macOS/Linux/Replit).

Alternatively, run each service in its own terminal:

```sh
python -m uvicorn src.main:app --host 127.0.0.1 --port 8080 --reload
npm --prefix src/frontend run dev
```

Next.js proxies `/api/*` to `BACKEND_URL` (default `http://127.0.0.1:8080`). FastAPI docs are at http://127.0.0.1:8080/docs. SQLite defaults to `src/data/future_ready.sqlite3`; set `APP_DB_PATH` to change it. Keep local data and credentials out of Git.

## Pages and integration

| URL | Behavior |
| --- | --- |
| `/` | Redirects to `/register`, matching main |
| `/register`, `/login` | Main’s onboarding/sign-in previews; no account creation or authentication |
| `/signals` | Profile skill → related AI skill → work change, with inspectable source passages |
| `/explorer` | Career matching, SDG mapping and synthetic scenario demo |

The skills workspace has two navigation destinations: AI trend signals and Career demo. Both use the shared workspace ribbon. The signals page starts with a fictional profile, lets the learner switch profiles and select one of that profile’s listed skills, then shows at most three supported AI-skill connections. The career demo uses generated synthetic career data. Former workspace URLs redirect to `/signals`. Onboarding answers remain in memory and are not silently copied into a profile. No page implements account security.

## Pathwaay model and data

The synthetic data is stored in `data/` at the repository root. Recreate it with `node scripts/generate_synthetic_data.mjs`, then train the local CPU models with `python scripts/train_career_models.py`. Model artifacts are saved under `models/` and excluded from Git; the backend trains them from the committed CSVs when needed. The SDG ranker uses curated synthetic skill-to-target weights across all 17 goals. SDG explanations can be generated by the optional RunPod GLM endpoint; configure `RUNPOD_API_KEY` and `RUNPOD_LLM_ENDPOINT_ID` in the backend environment. Career inference uses the local scikit-learn model by default, or an optional RunPod career endpoint when `RUNPOD_ENDPOINT_ID` is configured.

## Replit and production

After installing Python and frontend dependencies, the Replit Run button uses `scripts/dev.py`. Only the frontend needs a public port; it proxies API calls to the local backend. The previous artifact/workspace configuration and unrelated database post-merge hook have been removed.

For a production server, build with `npm --prefix src/frontend run build`, run FastAPI without `--reload`, and run `npm --prefix src/frontend run start`. Configure `BACKEND_URL` when building if the API is not at the default address. Replit deployment and durable SQLite storage must be configured and verified separately; the development launcher is not a production deployment configuration.

RunPod is optional. FastAPI can use the local career model without RunPod. Generated SDG explanations require a configured RunPod language-model endpoint; the fixed SDG reference text and dataset-ranked goals do not. `runpod/handler.py` is a Serverless handler for career inference and requires the included synthetic dataset at deployment.

## AI Trend Signals data

`/signals` has **For your skills** and **Explore AI skills** views. The first reads `GET /api/trends/connections?sample_id=cs-student&skill_id=local:python-programming`; a saved demo profile can supply `profile_id`. The second reads `GET /api/trends/explore-ai-skills`. Normal GETs read saved profiles and source data, never fetch a provider or invoke RunPod. A missing skill connection can insert one deduplicated discovery job when model processing is enabled. Background work checks Remote OK and OpenAlex at most daily and DOSM at most weekly when due, retains the last successful source data on failure, and processes changed evidence. Set `EVIDENCE_AUTO_REFRESH=0` to disable the scheduler. Older title/tag-only caches cannot support passage-level connections.

No current-skill → AI-skill pair is prewritten. Canonical skill and AI-capability aliases help identify source phrases; they do not prescribe recommendations. The processor extracts exact skill and work-task passages from retained descriptions, forms candidates from a source-supported AI task plus an explicitly named skill, and publishes only same-task links or pairings appearing across at least two independent employers. Weaker candidates stay in `signal_connection_reviews` as pending. Extraction is cached by source ID, document ID, content hash and version. Published connections have an evidence version and retain source IDs, publication/retrieval dates, quotes, role scope and conditional counts. A same-posting pair is labelled as an observation, not proof of how work changes. A model-reviewed explanation can add a cautious interpretation; invalid or insufficient output is rejected or retained separately. The bounded Remote OK sample cannot establish global or Malaysian demand, growth, decline or replacement. OpenAlex research remains available to other endpoints but is not mapped broadly onto these skill cards. Career Demo’s synthetic classifier remains separate.

Exploration ranks exact AI-capability mentions. With the current short, overlapping snapshot history it says **Most mentioned in our remote-job sample**, with a numerator and the current retained-posting denominator. It switches to **Fastest rising in sampled postings** only when snapshots span at least 60 days with at least two collections in each comparison window, two non-overlapping 30-day publication windows each have at least 30 unique postings, and each ranked skill has at least five mentions in both periods. Then it displays percentage-point share change and both period denominators. The small capped source limits occupation coverage; sparse skills are withheld rather than filled with model claims.

Optional extraction and discovery use the same server-side RunPod client and default GLM-5.3 endpoint configuration as Career Demo’s SDG text generation. `RUNPOD_LLM_ENDPOINT_ID` and `EVIDENCE_LLM_MODEL` may override the endpoint/model. With `EVIDENCE_LLM_ENABLED=1`, `RUNPOD_API_KEY`, `EVIDENCE_LLM_REQUEST_BUDGET` and `EVIDENCE_LLM_TOKEN_BUDGET` configured, a background job processes up to two uncovered skills per pass, at most two relevant documents per skill and one connection review. Operators can run `.venv/bin/python -m scripts.prepare_skill_connection_model run-queue`, `extract DOCUMENT_ID`, or `explain CONNECTION_ID`. Two versioned structured prompts extract source facts and assess relationships. Literal quotes, evidence IDs, relationship strength and overclaims are checked before publication. The request/token budget is shared with older signal wording jobs and is not a guaranteed dollar cap. No model runs on page load, and no paid infrastructure is created automatically. When model processing is off, deterministic source extraction still works and unsupported skills show an honest empty state.
